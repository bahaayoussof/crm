### Closed decisions
- Foundation uses separate `client` and `server` npm packages with root script delegation.
- Prisma 6 targets PostgreSQL with the CRM domain schema defined.
- `User` is the authenticated identity; a portal user optionally links one-to-one to `Customer`.
- Ticket messages have one required `User` author; escalation uses `TicketStatus.ESCALATED`.
- `TicketMessage` is public-only; internal notes use `TicketNote` or `CustomerNote`.
- Attachments support optional ticket, message, and customer contexts with later service-level invariant enforcement.
- Public registration is strict and CUSTOMER-only; it creates `User` and `Customer` transactionally.
- Authentication uses an eight-hour JWT access token, local browser persistence, `/auth/me`, and server-authoritative role middleware.
- Manually created customers have no login identity; deletion is blocked for linked identities or any support history.
- Customer activity is derived from customer timestamps and internal notes; attachments are read-only metadata until storage infrastructure exists.
- Frontend language is persisted under `crm-language`; English is the fallback and Arabic sets root document direction to RTL.
- The current shell exposes only implemented destinations, uses a desktop sidebar and compact mobile header/nav, and keeps portal navigation visually simpler.
- Agents see assigned and unassigned tickets only; workflow/priority changes require assignment, while assignment and escalation are ADMIN/MANAGER-only.
- Ticket deletion is unavailable; manual reopening, conversation, automation, notifications, attachments, portal ticket flows, and AI remain later features.
- Internal users are `ADMIN`-administered only (create/edit/role-change); accounts are retired via `User.isActive=false` (blocks login and `/auth/me`), never deleted; user administration acts on internal identities only, never portal customers.
